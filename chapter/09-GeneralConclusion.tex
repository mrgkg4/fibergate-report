\chapter*{General Conclusion}
\addcontentsline{toc}{chapter}{General Conclusion}
\thispagestyle{MyStyle}

The FiberGate project delivered a production-validated intelligent automation ecosystem for the Guichet OI: PAR France unit of Orange France, built over twenty-five weeks by two engineering interns operating simultaneously as production consultants and system architects. The dual role was not a methodological choice but an operational necessity and it proved to be the most important design constraint of the project. Every technical decision documented in this report is traceable to a concrete situation encountered in the production workflow: the regular expression that correctly captures alphanumeric PC codes such as DP0610012500255 was hardened because the initial \texttt{\textbackslash{}d+} pattern silently truncated a real code extracted from a live email; the atomic assignment design of Agent 2 was sharpened because a CAFF return sat unrouted for hours during a peak afternoon; the round-robin persistence index of Agent 3 was specified after observing, across multiple days, that a stateless distribution reset to position zero each morning systematically over-assigned the first consultant on the list.

The SENTINEL Automation Fleet, documented in Chapter 4, replaced three of the four primary manual workflows through a hybrid Python and Power Automate architecture that required no commercial RPA licence, no browser session, and no cloud connectivity beyond the Orange corporate proxy. The choice of exchangelib over UiPath, Blue Prism, and Selenium was dictated entirely by the deployment constraints of the Orange environment: the Exchange Server at exchange.itn.intraorange is reachable only via EWS/NTLM from within the corporate network, making all cloud-based RPA connectors structurally incompatible, while Selenium's DOM-based OWA access introduced fragility at multi-level folder navigation and could not programmatically mark emails as read. The EWS protocol-level approach resolved all three limitations simultaneously. Agent 1 reduces POI validation processing from fifteen to twenty minutes per email to under sixty seconds, a reduction of approximately 95 percent, recovering an estimated five hours of analytical capacity per working day at the unit's observed email volume. Agent 2 eliminates the structural routing gap for CAFF returns by binding OEIE extraction and consultant assignment into a single atomic Power Automate flow invocation, guaranteeing that the one-working-day contractual KPI is met for every return regardless of arrival time. Agent 3 compresses the Pilot's daily distribution routine from thirty to forty-five minutes to under six minutes including webhook dispatch, while introducing algorithmic fairness through a persistent round-robin index and continuity-of-treatment routing through dual Planner cross-referencing.

The FiberGate AI Service, documented in Chapter 5, addresses the LOC PAR completeness verification workflow through a LayoutLMv3 multimodal transformer fine-tuned on an in-house annotated corpus of administrative documents. The selection of LayoutLMv3 over LayoutLMv2, UDOP, Donut, and LiLT was grounded in a comparative analysis balancing parameter count, GPU memory requirement, and benchmark performance against the hardware constraints of the project: LayoutLMv3's unified self-attention mechanism over all three modalities at 125 million parameters and 7 GB VRAM provided the most favorable cost-performance ratio within the available infrastructure. The two-head fine-tuning strategy --- a sequence classification head for six-class document categorization and a BIO token classification head for twelve-field extraction over a twenty-five-label BIO space --- achieved 87.7 percent document classification accuracy (macro-F1 0.867) and a span-level macro-F1 of 0.448 on field extraction across the twelve fields in the held-out evaluation partition (Table 5.10). The strongest field, Référence Urbanisme, reaches an F1 of 0.926, with the representative-name and commercial-operator fields at 0.800 and 0.727 respectively; two fields exceed F1 = 0.75 and qualify for full automation, four occupy an acceptable review-assisted middle range, and three table-bound numeric fields remain at F1 = 0.000 pending further annotation. The confidence gate calibrated at per-token confidence 0.60 and span-level F1 0.70 ensures that uncertain extractions are routed to human review rather than silently committed, preserving the audit integrity that the regulatory context requires. Nine pipeline defects covering coordinate system mismatches, WordPiece alignment errors, and label-mapping persistence failures were identified and corrected between the first and final training runs, raising the span-level macro-F1 from 0.070 to 0.448, a result that underlines the observation that the gap between a trained model and a working production system is predominantly an engineering gap rather than a research gap.

The Unified Platform, documented in Chapter 6, integrates the SENTINEL Fleet and the AI Service under a single governed interface. The Angular 17 frontend communicates over JWT-authenticated HTTPS with a Spring Boot 3.2.4 backend implementing a hexagonally-influenced three-layer architecture, Spring Security method-level RBAC, and Spring Data JPA persistence to a managed PostgreSQL database accessed through a private endpoint within a segmented Azure Virtual Network. The FastAPI asynchronous execution layer exposes the three Python agents as background jobs retrievable by UUID, enabling the platform's real-time monitoring dashboard to poll for completion and stream structured execution logs without blocking the HTTP request lifecycle. The CI/CD pipeline spans GitHub Actions for build and test automation and Azure DevOps for release management, deploying each tier to Azure Container Apps with blue-green revision swapping for zero-downtime production releases. The measured business impact of the full ecosystem (Table 6.1) is an approximately 95 percent reduction in processing time across the three automated workflows, an estimated 12,320 hours of analytical capacity recovered annually, and a projected financial return of approximately 554,400 euros per year, with the development investment recovered within the first two months of production operation.

The project also has limitations that must be acknowledged. Three field types in the AI extractor --- Nb\_log\_res, Nb\_log\_pro, and Nombre\_Logement\_Lot --- have a span-level F1 of zero in the current deployment, attributable to the 512-token context window of LayoutLMv3 being insufficient to jointly attend to dense table column headers and their corresponding data cells. The correction capture and continuous improvement loop has been fully implemented but has not yet completed a retraining cycle in production; its effectiveness therefore remains an engineering assumption pending the first two months of correction accumulation. The platform's Azure hosting configuration is deployment-ready but awaiting the formal Mantu Group subscription approval that will activate the production tenant.

These limits define a concrete handoff roadmap. The tabular field problem requires either a model with an extended context window such as a long-document transformer variant, or a preprocessing step that isolates table regions before sending them to the extraction head. The retraining loop maturity requires only time and annotated data, both of which are now accumulating. The Azure tenant activation requires only administrative approval, not additional engineering work. None of these limits diminishes the value already delivered; each is a precisely bounded engineering problem with a known solution path.

Beyond the metrics, the project demonstrates that production-grade intelligent automation in a regulated operational environment is achievable within the constraints of a final year internship when the engineers are given genuine operational context, access to live data, and the organizational trust to deploy in production. The FiberGate architecture, a hybrid Python and Power Automate automation layer, a fine-tuned multimodal document AI service, and a unified Angular and Spring Boot governance platform over Microsoft Azure and Microsoft 365 offers a replicable engineering blueprint for administrative automation in the telecommunications and infrastructure sector. Three additional Orange France departments and two external Amaris clients have already been identified as candidates for adaptation of this model, a validation that the architectural choices made under the specific constraints of the Guichet OI environment generalize beyond the project that produced them.
